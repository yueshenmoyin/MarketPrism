# MarketPrism · 观澜

**An AI stock research workspace with multiple perspectives on the market.**

[中文文档](README.md) · [Deployment guide (Chinese)](docs/a-share-server-deployment.md) · [Contributing](CONTRIBUTING.md) · [Security](SECURITY.md)

MarketPrism brings multi-agent research to a Chinese A-share desktop workflow. It combines a React / Tauri interface, Python APIs, configurable language models, market-data adapters and self-hosted analysis services.

This is an early-stage research application. It does not connect to brokers or place real orders, and it makes no claims about investment returns or prediction accuracy.

## Features

- **Multiple research perspectives:** market, fundamentals, news and sentiment analysts feed bull/bear discussions and risk evaluation before the final report.
- **Chinese A-share workflow:** stock search, symbol normalization, Chinese reports and localized ratings.
- **Desktop research experience:** progress events, research stages, saved reports and PDF export through the system print dialog.
- **Configurable models:** separate quick/deep reasoning models, domestic provider presets, OpenAI-compatible gateways and Ollama adapters.
- **Data-source flexibility:** AkShare by default, optional BaoStock and Tushare integrations, with coverage varying by endpoint.
- **Self-hosted services:** account administration, data caching, optional periodic prewarming, analysis jobs and report storage.
- **Developer-friendly structure:** Python, FastAPI and LangGraph research modules, TypeScript frontend and Rust desktop shell, with automated tests.

Multiple agent perspectives are not independent fact verification. Generated reports still require human review.

## Architecture and privacy

The desktop UI calls a local API on port 8765. By default, this API forwards authenticated data and research requests to your own server, whose default local port is 18080. Both processes can run on the same computer.

Login is part of the default desktop workflow. No hosted server, account or model credits are bundled. Local analysis can be configured separately; it does not remove desktop authentication.

Local-first does not mean offline: cloud model providers receive research inputs, and market-data adapters use external services. Desktop configuration may contain credentials and must remain private.

## Getting started

Requirements: Python 3.10+ (3.12 recommended), Node.js 20.19+ or 22.12+, and Rust / platform build dependencies for the native desktop application.

```powershell
git clone https://github.com/yueshenmoyin/MarketPrism.git
cd MarketPrism
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
npm ci
```

Configure the server process with your own `AITRADE_AUTH_USERNAME`, `AITRADE_AUTH_PASSWORD`, writable `AITRADE_AUTH_USERS_FILE`, model provider, model names and credentials. Run `python -m aitrade.server.auth_api`. In a separate activated terminal, set `AITRADE_AUTH_SERVER_URL=http://127.0.0.1:18080` and run `npm run tauri -- dev`.

See the [complete configuration commands](README.md#快速开始) and [deployment guide](docs/a-share-server-deployment.md). `.env.example` is a reference. When python-dotenv is installed, package initialization searches upward from the working directory for `.env` and `.env.enterprise`; existing process variables take precedence. Prefer explicit environment injection in production.

For browser-only development, run `npm run desktop:api` and `npm run dev` in separate terminals. For Windows packaging, run `npm run package:windows`. Other native platform packages require additional configuration and verification.

The internal Python package name `aitrade`, `AITRADE_*` variables, `.aitrade` storage paths and internal application identifiers are retained for compatibility.

## Limitations

The primary workflow is post-market A-share research, not real-time trading. Public data can be delayed or unavailable, models can hallucinate, and in-memory jobs can be interrupted by server restarts. Model and infrastructure costs are the user's responsibility. Production self-hosting requires appropriate HTTPS, access controls and operational safeguards.
